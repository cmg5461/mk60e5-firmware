What each parameter in the M3 stability-control firmware actually changes — by subsystem, with the algorithm it feeds and the direction of its effect.

Scope. Static analysis of the owner's own ECU, for understanding and comparison. Stock values are quoted so edits are legible against a baseline. Not a recipe for disabling the safety system on a road car: the strongest levers (DSC mode, the active variant) are EEPROM, not flash, and every edited image must be re-signed to load.

Architecture

Once per 10 ms frame the main task walks a fixed 41-call sequence: read sensors, estimate vehicle state, let each controller decide, arbitrate per wheel, run the pressure model, drive the valves, and send a torque request to the engine.

Editing & re-signing

An edited image is rejected until two integrity values are recomputed — both solved and tooled.

LayerWhatFix
ROM self-testHardware MISR over three regions; calibration region [0x40300, 0x4249C), expected word at 0x4249C.Recompute after any cal edit.
BMY signature512-bit RSA (e=7) over the application, in the trailing BMY block. Key recovered.Re-sign after the MISR fix.

One command: python tools/bmy_resign.py fix <edited.bin> recomputes the MISR words then the BMY signature; verify reports both. Whether the bootloader enforces the signature at flash time is in the absent 0x0–0x47FFF region — treat edited images as research-only.

Vehicle model

Wheel speed & tyres

The four wheel speeds are the root of everything — vref, slip and the broadcast vehicle speed derive from them. Tyre circumference is the scale factor; the M3 ships the same geometry as the 1M.

Sensor type: stock M3 and 1M images configure all four channels for VDA active sensors. There is no coding or calibration selector. E46-type 2-level (7/14 mA) sensors work with a 4-byte firmware patch (bench-verified on all four wheels, 2026-10-06): ASIC mode mask 0x28C → 0, both-edge timer capture, direction mask 0, presence mode 2. ABS slip & deceleration

ABS arms a wheel when its slip or deceleration crosses a speed- and grip-dependent threshold. The per-wheel phase state machine then cycles dump → hold → reapply.

Key detail: the real arming threshold is the gross-slip curve at 0xD6CE2 (≈4 km/h low-speed, rising to ~11 % of vref) with a persistence counter. The small 0x40DB6 "entry-slip" curve (1.3–2.0 km/h) is used only inside the pair-logic partner test.

Decision code 0x408DDE classifies each cycle: 1 no rear control · 16→8 select-low rear build · 2 pair-hold · 32 yaw-limited build (0–100 % lag) · 256 cornering reapply.

M3 vs 1M: core slip/decel targets are identical for variants 1–9; only 10/11 are more permissive at high speed. The M-car's licence lives in the yaw/DSC-mode logic, not these numbers.

Pressure & hydraulics

The controller works through a volume model: each wheel's fluid volume is tracked, converted to pressure through the COA p–V curves, and changed by valve flow Q = √Δp · opening · k. A low-pressure accumulator holds dumped fluid; a return pump drains it.

Traction (TCS)

TCS acts on the driven (rear) wheels. Drive slip = rear − same-side front (0.01 km/h). Past the target curve, a PI loop requests engine-torque reduction and, if needed, brake pressure. The DSC mode (0/1/2) picks the set.

Yaw control & DSC mode

Where the M-car's character lives. AYC compares measured yaw to the model target; past the entry threshold it brakes individual wheels and cuts engine torque. Three DSC modes scale how much it allows — mode 1 is by far the most permissive.

Where "MDM" lives: the AYC tables are byte-identical to the 1M. The M-specific permissiveness is which mode the coding bit selects (m1 vs m2), not a different number. The mode ceilings are the lever, not the slip/decel targets.

How AYC brakes: the PD moment picks one wheel by the sign of the yaw error — oversteer brakes the outer front; understeer the same-side rear (rear-share 0x4155E, stock rear-only; front-outer pre-fill 0x411B4 = 5 bar). The engine-torque cap min-merges into the same TX 0x0B6 request as TCS. The yaw observer (0x5EBC4) is a nonlinear single-track model with a per-variant friction-limited tyre-force knee.

Brake coding

Brake hardware is described by pressure↔volume curves, selected by a 3-bit front and 3-bit rear coding field. Rotor and piston geometry are folded into these curves. The blocks are byte-identical to the 1M; coding picks code 0 vs 1 per axle.

Steering (CSI)

Steering angle (F-CAN 0x0C9) is converted to a road-wheel angle through a variable steering-ratio curve, then fed to the yaw reference. One of the few genuinely M3-specific calibrations — it grew and the ratio curve differs.
