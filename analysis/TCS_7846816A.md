# Traction control (brake TCS, engine ASR, MSR) — 7846816A (E9x M3)

How the DSC controls the driven (rear) wheels: the reference speed and drive-slip signals, the three traction
channels (brake traction control, engine torque reduction, engine drag-torque control), what triggers each, the
pressure and torque laws, the DSC modes and inhibits, the torque arbiter and CAN 0x0B6, the numeric limits and what
each calibration does.

Read from the disassembly (`analysis/7846816A_main.lst`), not bench-tested. CPU addresses; file = CPU + 0x8000.
Tags: **[C]** read from code on this image; **[R]** read from code *and* replayed with `tools/mcore_replay.py`
against the closed formula given here (case counts in §13); **[I]** inferred; **[open]** not traced. Units: speed
0.01 km/h, pressure 0.01 bar, slip rate ≈ 1 mg (§2.3), yaw 1/20000 rad/s, `curve(a, x)` = `curve_interp_s16`
0x710FC on the `curve_t` at a, `m` = DSC mode index (§3.1). Everything runs every 10 ms in task 3 (§1.2).

Related: `AYC_7846816A.md` (yaw control; shares the mode index m and the arbiter), `HYDRAULIC_MODEL_7846816A.md`
(wheel pressure PM, request arbiter), `WHEEL_SPEED_CHAIN_7846816A.md` (`wheel_rec` fields), symbols
`7846816A_symbols.md` § "Traction control (TCS / ASR / MSR)", FACTS "[disasm 2026-10-26] Traction control".

## 1. Overview

### 1.1 The three channels [C]

The module (0xC7000–0xCFA00, about 150 functions) holds three independent controllers. Earlier notes called them
channels A / B / C after their state functions; the roles are now settled by their outputs:

| Channel | What it does | Output | Active flag | State fn | Inhibit word |
|---|---|---|---|---|---|
| **A, brake TCS** | brakes a spinning **rear** wheel | target pressure `0x402FEC[w]` → `req_arbiter_submit` id **2** (0xC8740) | `0x402FC0` b4 (= b0) | 0xC779A | `0x403004` |
| **B, engine ASR** | cuts engine torque while the rears over-spin | torque limit `0x402F7A` → arbiter 0xCC2C2 reduction branch (`0x402F6D` b3) | `0x402F6C` b7 | 0xC7818 (the lamp's "TCS") | `0x402F84` |
| **C, MSR** | raises engine torque when engine braking locks the rears | `0x40304C` → arbiter increase branch (`0x402F6D` b2, 0x19E bit 4 "MSR") | `0x40303C` b7 | 0xC789C | `0x403048` |

This resolves the old open question in FACTS ("which of A / B is engine ASR and which is brake TCS") and corrects
the cycle-4 note that `tcs_torque_pi` 0xCD1E8 is the TCS torque-reduction PI: it is channel C, MSR (§6, §11).

### 1.2 Data flow and scheduling [C]

```
wheel_rec rec+0x1C (tyre-corrected), rec+0x1A (raw)            task3 10 ms, wheel loop 0x8F028 → 0xC953C
  ├─ front trackers 0x403076/78 (0xCD9D0, 0xCDBA0) ── vref_tcs 0x403066 = min      (§2.1)
  ├─ drive slip 0x40307E[w] = wheel − same-side tracker (+ yaw term, rears) 0xC9450 (§2.2)
  ├─ filtered slip 0x403086[w] 0xC9368, slip rate 0x40308E[w] 0xC93E2             (§2.3)
  └─ CBAE4 / CC7DE / C9298 (channel B helpers), C91A4 axle-oscillation flag

control dispatcher 0x8CCB8 (task 3, after the wheel loop):
  slot  6  0xCC26C  DME torques → wheel domain 0x402F70/72, gearbox bit 0x402F6C b4
  slot 14  0xCF120 → 0xC8238   channel A: flags, limits 0x403014/0x40300C, per-wheel evaluation 0xC7E40
  slot 15  0xCF17A → 0xC95B8 (engine-bog 0x403024), 0xC82F0 (active flags), 0xC8866 (pressure law + submit)
  slot 16  0xCBF58             channel B: targets 0xCB27A, controller 0xCAF26, inhibits 0xCE1E8, → dsc_mode_select
  slot 17  0xCC9A0 → 0xCC9B4   channel C: MSR slip, target, PID; tail 0xCD7FE (floor 0x403060)
  slot 23  0xCC2C2             arbiter → 0x402F74/76 + type 0x402F6D → CAN 0x0B6 (0x7F530)
  slot 32  hydraulic pipeline executes the id-2 brake request
```

Slot 14/15 skip channel A entirely while `0x402F6A` b3 (channel A inhibited) is set, and zero
`tcs_driveslip_threshold` 0x402FC2 [C]. The dispatcher also skips `abs_pm_snapshot` 0x559CC while `0x402FC0` b0
(brake TCS active) is set [C].

## 2. Shared signals

### 2.1 Reference speed [R]

Each front wheel has a rate-limited tracker f (`0x403076` left, `0x403078` right) of its tyre-corrected speed v =
rec+0x1C, updated by `tcs_front_tracker` 0xCD9D0 with a hold timer h (0x40307A/7B) and a rise counter c
(0x40307C/7D):

```
v ≥ f (rising):  f < 5 km/h: f' = min(v, f + 0.22), c = 0;   else f' = v
                 if v − f > 2.14 km/h: c < 3 → c += 1, f' = f + 2.14   (else c = 0)
                 h = 60 if ASR active (0x402F6C b7) else 80
v < f (falling): c = 0, h −= 1; while h ≥ 50 f is held (10 frames with ASR, 30 without)
                 then f' = f − 0.05 (ASR active) | f − 0.45 (h = 0 and both rears below vref_tcs) | f − 0.11
                 if f' < v: f' = v + 0.05
```

Fall rates per 10 ms: 0.11 km/h = 0.31 g, 0.05 = 0.14 g, 0.45 = 1.27 g. `tcs_vref_update` 0xCDBA0 then:

- picks the update: in a braking regime (0x401FF2 b7, demand torque 0x401144 < 250 or pedal < 20, a wheel in an ABS cycle,
  0x408DA1 b4) `0xCDB00` tracks max(v_front, ABS vref 0x408DA8) falling at most 0.45/frame; with `0x402F6C` b5
  `0xCDB42` tracks the raw front maximum and lets f fall 0.45/frame while the faster rear is below it; otherwise
  0xCD9D0 per front [C];
- `vref_tcs` **0x403066 = min(f_L, f_R)** [C];
- during an AYC front-wheel intervention (0x400AFA/B b6 with 0x400B0C/E > 0) the braked front's tracker is set to
  vref_tcs [C];
- `0xCDAA6` keeps each tracker at least vref − max(5.12 − vref/67, 0) km/h (vref in km/h), and re-seeds a front
  below 2.5 km/h to vref [C];
- with ASR active and the front axle in ABS (0x408DA2 b7) or 0x4030B5 > 90, the lower tracker is pulled up to the
  higher − 0.05 km/h [C].

### 2.2 Drive slip and the cornering term [R]

`tcs_slip_raw` 0xC9450:

```
0x40307E[0] = FL − f_L    0x40307E[1] = FR − f_R          (fronts, used by channel B only)
0x40307E[2] = RL − f_L + t 0x40307E[3] = RR − f_R + t     (rear − same-side front, wheel = rec+0x1C)
y = |yaw 0x403074| / 75   if tcs_sensor_valid 0x403064 b3, else 2·0x4030A8 (front Δv, §2.4)
v = max(vref_tcs, 0.50 km/h);   x = (y·2048) / v
t = ((v · k1(x)) >> 10) · k2(v) >> 10
    k1 = interp 0xF6158 → 0xF6168 (8 pts, ≈ quadratic: 0,5,24,51,92,143,205,270 at x = 0..357)
    k2 = interp 0xF6178 → 0xF618A (9 pts, 1024 at 0 → 768 at 20 km/h → 0 at 40 km/h)
```

t adds the rear-path deficit of cornering to the rear slip, so turning at low speed does not read as drive slip.
At 20°/s it is 1.30 / 0.72 / 0.30 / 0.10 / 0 km/h at 5 / 10 / 20 / 30 / 40 km/h. The 20 km/h value matches the
kinematic deficit v·L²κ²/2 ≈ 0.3 km/h (L = 2.76 m) [I physical check]. Above 40 km/h t = 0. Drive slip is an
absolute speed difference; there is no percentage slip anywhere in the module [C].

### 2.3 Filtered slip and slip rate [R for the filter, C for the rate]

Rears only (wheel records 0x40BF80 / 0x40BFC0):

```
0x403086[w] = s + k·(f − s)/256,  k = trunc((256·N − 2560) / N)      (s = raw slip, f = old filtered)
              N = 150 if rec+0x10 b4, 110 if split-µ (0x402F7E b7), else 30   → α = 10/N per frame
0x40308E[w] = 10·q + (rate − 10·q)·233/256,  q = trunc(28·Δ/10),  Δ = filtered slip change per frame
              (forced to 0 when rec+3 b0, rec+4 b7 clear, rate < 0 and Δ ≥ 6)
```

One count of Δ is 1 km/h/s = 28.3 mg, so the rate unit is ≈ 1 mg (the 28 is a rounded 28.3) [C formula, I name].

`0xC91A4` sets the **axle-oscillation flag** `0x402FFC` b1 for 56 frames (cleared below 28) when the two rear rates
have opposite signs beyond ±320 mg, their mean is ≤ 625 mg, and the summed filtered slip is < 1 km/h. It is also
cleared when 0x403024 > 150. Pairs come from table 0xF619C [C formula, I purpose].

## 3. Modes and inhibits

### 3.1 Mode variables [C]

- **`tcs_mode` 0x4030A2** (`tcs_mode_from_driver_mode` 0x8DA30): 1 DSC on, 2 DSC off, 3 MDM.
- **m = coding block + 7 (0x4031B1)**, written by `dsc_mode_select` 0xCF2E8 at the end of slot 16: m = 0 unless MDM;
  in MDM m = 2 if coding byte 10 bit 5 ("USA M-Dynamic mode"), else 1. So **DSC on and DSC off both run m0**. Every
  per-mode TCS table is indexed by m. The AYC tables use the same index (AYC doc §7).
- **`0x402F6C` b4** = `gearbox_type` 0x40114D ∈ {1, 3} (slot 6). It selects the alternate brake-TCS threshold set
  0xF61F6 and a pedal term in the ASR target. The M3 coding allows only gearbox 0 (manual → type 0) or 2 (DCT →
  type 6), so **b4 is never set on a validly coded M3**, and those alternates are dead data here [C].

### 3.2 What disables each channel [C]

| Cause | A, brake TCS (`0x402F6A` b3 via `0xCE3D0`) | B, ASR | C, MSR |
|---|---|---|---|
| Fault reaction `0x402880` | b4, latched (0x403004 b7) | b3 (0x402F84 b1) | b5, latched (0x403048 b6) |
| `0x40288C` b5 | yes | yes | yes |
| DSC off (tcs_mode 2) | latched 0x403007 b2 → state 7 | latched 0x402F84 byte 1 b2 → state 7; ASR exit request (0xCA074) | **no DSC-off bit**; output forced to 0 only with `dme_0A8_flags` b4 (§6.4) |
| Speed | **ABS vref > 120 km/h while idle** (0x403005 b6, literal 12000) | — | — |
| Disc overheat | `0x402FFF[w]` b3 from `0x402FC0` b1 (§4.7) | — | — |
| DME "torque not adjustable" 0x40114F b5 | 0x403007 b6 | 0x402F84 byte 1 b7 | — |
| Pedal | > 13 % sets mask bits b6–b3 only, not the inhibit b7 [C; effect of those bits open] | exit at pedal < 13 (§5.5) | > 13 % inhibits (0x403048 b2) |
| Other | 0x4030A4 = 3 (0x403007 b0); 0x402F6C b5 (0x403005 b4) | — | A, B or AYC active (b5); low-speed lock count 0x403056 ≥ 15 (b4) |

Latched bits release when the cause is gone **and** `0x402F86` b2 is set. A running intervention is allowed to
finish: the state functions return 7 (off) / 6 (inhibited) only when the channel is not active. Missing steering or
DME frames set the fault-reaction bits, so all three channels go off (FACTS "Steering-sensor loss").

## 4. Channel A — brake traction control

### 4.1 Entry and exit limits [R]

`tcs_driveslip_total` 0xC7996 and `tcs_a_limits` 0xC7A92, per rear wheel w:

```
T  = curve(0xF625C + 34·m, vref_tcs) + trunc(0x4030B6 / 4)          → 0x402FC2
     (0xF61F6 + 34·m instead when 0x402F6C b4 — never on the M3)
R  = trunc(p · rate[w] / 100),  p = 2 if split-µ and rec+0x10 b4 clear, else 10
E  = curve(0xF62EE + 28·m, vref_tcs)   if not split-µ, 0x402F7E b4 clear and vref_tcs ≥ 2.5 km/h, else 0
T += 0xF62C2[m] · 0x4030A8             on the side picked by 0x402F7F b7 (ay sign) when 0x402F7E b2 (|ay| > 0.42 g)
T += 20000                              if tcs_mode = 3 and 0x402FC0 b6 clear (unreachable in practice, §4.6)
entry 0x403014[w] = T + E − R + 5.00 km/h        exit 0x40300C[w] = T + E/2 − R + 3.00 km/h
if entry ≥ 300 km/h: both = 300 km/h
```

The +5 / +3 km/h offsets are code literals here (cal fields +0x1DE / +0x1DC on the 1M). R lowers both limits while
the slip is rising: +1 g of slip acceleration lowers them 1 km/h. Limits with R = 0 and no cornering or split terms
(km/h, entry / exit):

| vref | 0 | 5 | 10 | 15 | 25 | 50 | 80 | 100 | 150 | 200 |
|---|---|---|---|---|---|---|---|---|---|---|
| m0 | 20.0 / 18.0 | 23.2 / 17.6 | 16.5 / 12.1 | 9.7 / 6.7 | 8.0 / 5.0 | 9.3 / 6.3 | 10.8 / 7.8 | 18.8 / 15.8 | 35.4 / 32.4 | 52.0 / 49.0 |
| m1 | 19.0 / 17.0 | 22.6 / 17.9 | 19.1 / 15.3 | 15.7 / 12.7 | 14.9 / 12.0 | 13.5 / 10.5 | 13.8 / 10.8 | 18.8 / 15.8 | 35.4 / 32.4 | 52.0 / 49.0 |
| m2 | 19.0 / 17.0 | 22.2 / 17.6 | 18.5 / 14.6 | 14.7 / 11.7 | 14.1 / 11.1 | 12.5 / 9.5 | 12.8 / 9.8 | 17.8 / 14.8 | 34.4 / 31.4 | 51.0 / 48.0 |

The curve alone (T at 0 / 15 / 25 / 50 / 80 / 100 / 150 km/h = 15.0 / 2.7 / 1.0 / 2.3 / 3.8 / 11.8 / 28.4 km/h for
m0) matches FACTS. Above 100 km/h the limits open fast, and the 120 km/h inhibit (§3.2) blocks new entries anyway.

### 4.2 Per-wheel evaluation [C]

`tcs_a_wheel_eval` 0xC7E40 builds a command byte for each rear wheel: b4 enter / build, b5 hold, b6 exit, b3 both
idle.

a = wheel acceleration rec+0x22 (0.01 g, WHEEL_SPEED_CHAIN doc).

- **Enter (b4)** when raw slip > 1 km/h, filtered slip > entry limit, and engine-bog margin 0x403024 ≤ 80
  (≈ 640 rpm under n_ref). If the wheel was holding, it must also have PM < 20 bar, split-µ set, or
  a > curve 0x40FC8(filtered slip) (1.5 g up to 15 km/h of slip, falling to 0.21 g at 28 km/h).
- **Hold (b5)** when:
  - 0x403024 > 110;
  - after the first step, filtered slip < 15 km/h with a < −0.5 g;
  - the slip rate is below curve 0xF61B4 (0 up to 40 km/h of slip, then −5 g at 60 km/h).
- **Exit (b6)**:
  - when filtered slip < exit limit + curve 0xF61CA(−rate) (0 → +12 km/h for a falling rate of 0.5–2 g), together
    with any of: a < 0, slip < 5 km/h, not split-µ, PM > 50 bar, or PM > 25 bar above 20 km/h. Outside split-µ,
    dropping below the exit band is therefore enough;
  - when raw slip < 0, or 0x403024 > 150;
  - from release or end (rec+4 b5 | b3) with rec+0x10 b4, unless entering;
  - from `tcs_lowspeed_pair_exit` 0xC7D48: below 30 km/h, when the other rear also spins (filtered > 1.2, raw > 3
    km/h, rate ≥ 0, PM < 5 bar), the wheel with more pressure, or the one beyond 20 bar, exits, and `0x402FFC`
    b5 / b6 (rear / front pair flag) is set.
- **MDM pair exit** (0x402FC0 b6 only, §4.6). When all of these hold, this wheel exits and `0x402FFF[w]` b1 is set
  (both spinning: hand over to the engine) [C condition, I purpose]:
  - the other rear is above 1.8 km/h filtered and 5 km/h raw (thresholds from 0xF6342, all zero → constants);
  - the other rear has rate > −0.25 g, a > 5 g, raw > 10 km/h, or was not active;
  - this wheel is within 10 km/h of it, or its rate is more than 0.6 g lower.

### 4.3 Phases [C]

The phase byte sits in the shared wheel record: rec+3 = this frame, rec+4 = last frame (0xC8238 copies rec+3 →
rec+4 and clears rec+3). Bits: b7 idle, b6 hold, b5 release, b4 build, b3 end, b2 first release frame, b1 active,
b0 first frame. `tcs_a_phase_update` 0xC7BB4:

- From idle, b4 starts build (b4 | b1 | b0) and arms the other rear as active-idle (b7 | b1).
- From build or hold: b6 → release (+b2), b5 → hold, b4 → build. Otherwise, while the fast fill runs, stay in
  build; when not split-µ → hold; if PM < 50 bar → build; else hold.
- From release: b4 → build; b3 → both rears idle; b6 → release; else end (b3).

`0xC82F0` sets `0x402FC0` b4 = b0 = (either rear has rec+3 b1). With the inhibit (0x402F6A b3), or ABS 0x408DA2 b6
while not active, it forces both rears to idle.

### 4.4 Pressure law [C]

Per-wheel record `0x402FC4[w]` (10 B): +0 PM (copied from `wheel_pressure_model` 0x4016E2 by
`hydraulic_model_step` 0x82EF4), +2 demand, +4 u8 fast-fill counter, +6 peak. Counters: `0x40301C[w]` steps
(≤ 20), `0x403020[w]` frames since the last step.

**Build (rec+3 b4, `tcs_a_build` 0xC9084):**

1. Phase start (rec+3 b0): peak = demand = PM, step and interval counters 0.
2. Fast fill, armed only on entry from idle with counter = 40 (the other rear gets ≤ 35), counts down every frame (≤ 0.4 s;
   0xC83C4). With e = filtered slip − entry limit − curve 0xF6424 (all zero):
   - demand = 3 bar + rate/8 + max(e, 0), at least PM + 5 bar;
   - the fill ends (counter = 0) when PM ≥ curve 0xF6408(vref) % × (3 bar + rate/8 + 0xF648A[m]·max(e, 0)/8),
     halved with the axle-oscillation flag. 0xF6408 = 100 % to 40 km/h, 67 % at 60, 0 at 100 km/h;
     0xF648A = 8 / 4 / 8.
3. Re-entry into build from hold or release (no fast fill): first demand = peak · (100 + g·rate/1000) % + 5 bar,
   g = 25 below 20 bar else 10 (rate > 0), capped at 130 bar.
4. Then **+5 bar every N frames**. N = map **0xF643A**[row][col], with row = (e − 3 km/h)/8 km/h (0…4) and
   col = (rate/10 + 130)/40 (0…7, rate/10 in 0.01 g):

   ```
              falling slip  ←                              →  rising fast
   e < 11:     98  80  60  45  32  21  11   5
   11–19:      98  70  50  42  21  14   7   4
   19–27:      98  60  45  28  11   7   5   4
   27–35:      70  56  42  14   7   5   4   2
   ≥ 35 km/h:  56  42  21  11   5   4   2   2
   ```

   2 frames = 250 bar/s; 98 frames ≈ 5 bar/s. Above 20 bar N grows by N·(demand − 20 bar)/28 bar. In MDM with the
   oscillation flag and no split-µ, N ≥ 15. With 0x403024 > 50, N ≤ 11 (< 20 bar) / 21; if e < 0, +14.
5. Steps stop while `0x402FFF[w]` b6 (freeze).

**Release (rec+3 b5, `tcs_a_release` 0xC8C5A):**

1. First frame: demand = d % of the peak, with d = 95 + rate·g/1000 for rate ≤ 0, g = 50 (< 20 bar) / 20 (oscillation)
   / 15 (rate < −1 g) / 10, halved in split-µ. In the low-speed pair mode (`0x402FFC` b5) d uses the *other* rear's
   −rate with g = 80 and is clamped to 50…80 %. If the result is not at least 3.5 bar below PM, the demand steps
   −3.5 bar instead.
2. Then −max(15 %, 3 bar) (capped at the demand) every N frames. N = map **0xF63B8**, with row = (exit limit − slip
   + 5)/5 km/h (0…4) and col = (rate/10 + 201)/25 (0…7):

   ```
                     fast recovery  ←          →  slow recovery
   slip > exit:       4   5   7  10  14  19  24  30
   0–5 below:         3   4   6   8  10  14  18  24
   5–10:              2   3   5   6   8  11  14  18
   10–15:             1   2   3   4   6   8  10  12
   ≥ 15 below:        1   1   2   2   3   5   6   7
   ```

   N = 2 when raw slip < 1 km/h or the demand is 0. In split-µ N × 5. Rear pair mode caps N ≤ 4. With
   0x403024 > 150, N ≤ k·(250 − 0x403024)/10 (k = 8 / 4).

**Target and smoothing (`0xC8576`):** `0x402FEC[w]` = demand, capped at **130 bar** (`0x89A7C(2)` returns the
literal 13000). A rise outside the fast fill is smoothed: target = new + ¾·(old − new), i.e. a quarter of the
step per frame. Decreases pass straight through. With the freeze bit (`0x402FFF[w]` b6) the old demand is reused.

### 4.5 Output [C]

`tcs_a_submit` 0xC8740, each frame for each rear not idle:

- `req_arbiter_submit(op 1, id 2, wheel, start, target, rate, flag 0xDA08D)` with start = PM, rate = target − PM.
  Within 1 bar, rate = 0 and start = target. `req_slot_step` ramps the arbitrated pressure, and the inlet/outlet
  logic executes it (HYDRAULIC doc).
- Circuit requests `0x835F0(circuit 0/1, id 2, bytes 0xDA08E | b7 b3 b1)` for both circuits: the USV/HSV/pump side
  of an active pressure build [C call, I meaning].

### 4.6 MDM pair mode, `0x402FC0` b6 [C]

`0xC81BE` (start of slot 14):

- In MDM (tcs_mode 3), b6 = 1 unless both rears are non-idle (then it is left as it was), so in practice b6 is
  always 1 in MDM.
- Outside MDM, b6 is only cleared (a rear filtered slip < 2 km/h, and not active or below 35 km/h), so it is 0.

With b6:

- the pair exit of §4.2 runs;
- the build demand is capped at 10·curve **0xF635E**(vref) = 170 bar up to 60 km/h, 50 bar at 70, **0 from 80 km/h**
  (`0xC9024`);
- the +200 km/h entry term in §4.1 is off (it needs b6 clear in MDM, which 0xC81BE does not allow except for a
  transient).

So in MDM brake TCS works only below 80 km/h, as a brake-based locking differential for one-wheel spin, and lets
go when both rears spin [I purpose].

### 4.7 Disc thermal model and brake-TCS cut-out [C, I units]

The model runs for **all four discs and all braking**: driver, ABS, AYC and TCS alike. It uses PM, the pressure
`hydraulic_model_step` copies into 0x402FC4[w].+0 (measured where the wheel sensor is valid).

- **Scheduling (`tcs_disc_thermal` 0xCEEDC).** A 23-frame round robin (counter 0x403038): slot 0 updates the
  overheat flag, slots 1–8 heat then cool wheel 0, 1, 2, 3 in turn, and slots 9–22 do nothing. So each disc gets one
  heating and one cooling step every **230 ms**, from instantaneous samples.
- **Heating (0xCEB0C).** E += ((PM · v) >> 16) · k / 100.
  - v = raw wheel speed rec+0x1A, 0 at or below the speed floor 0x4032D0.
  - PM is clamped to 130 bar while brake TCS is active.
  - k = 0xF674E[coding f+3] (front, 65) or 0xF6752[coding f+4] (rear, 45).
  - Saturates at 0xFB1E.
- **Cooling (0xCEBAE).** d = (a · ABS vref) >> 10 + b, so airflow cooling grows with speed. Then:
  - below 0x37CE: E −= d·E/2¹⁶ (∝ E);
  - 0x37CE…0x8B82: E −= d·E²/2³² (∝ E²);
  - above 0x8B82: E −= d·150/256.

  Never below 0x0B3B (fixed ambient; there is no outside-temperature input). Coefficients (a, b) by brake code:
  front 0xF6736 / 0xF672E (4 / 7), rear 0xF673A / 0xF6732 (4 / 10); above 0x37CE front 0xF6746 / 0xF673E (11 / 35),
  rear 0xF674A / 0xF6742 (11 / 42).
- **Cut-out (0xCEC7C).** The hottest **rear** sets `0x402FC0` b1 at ≥ 0x9976 and clears it at ≤ 0x6F9B. b1 is copied
  to both rears' `0x402FFF[w]` b3, which inhibits channel A (§3.2). Front values are only read outside the module
  (0x6F8BA, 0x94EC4, 0xC0B46; open).
- **Persistence across key-off.**
  - At power-down (0xCEA0E, state 0xCE990 = 1) the high byte of each 0x402FF4[w] (256-count resolution) and a
    timestamp 0x403034 = the CAN 0x310 relative time 0x401128 are packed with XOR checksums into 0x403029… and
    queued to NVM (`nvm_queue_job` 0x6E16C, job record 0xF61A8).
  - At start (0xCEEDC, `0xCED08`), elapsed = now − stored (≤ 0xE100), and `0xCED38` cools each disc for
    min(elapsed, 0x1C20)·1000/224 steps using the b terms.
  - If 0x310's time is invalid (0x40112C b7) the cool-down is skipped and retried every frame, so it never happens.
    The discs then start at the saved values and cool only while driving.
  - If there is no stored timestamp, the cool-down is skipped once.
  - The restore itself (0xCE99A, checksum checks 0xCE958 / 0xCE974) is not traced step by step.

At 0.014 per count the constants read 40 (ambient floor) / 200 / 400 / 500 / 550 / 900. That looks like °C [I]: cut
out at 550 °C, back in at 400 °C. The 0x310 time unit (seconds?) and so the 2 h (0x1C20) / 16 h (0xE100) caps are
also [I].

The 1M kept the same words as TCS cal fields +0x8FE…+0x930. The 1M report called them "integrity/id words", which is
wrong (§11).

**Re-use on another car.** Heating per count is energy ∝ (torque per bar) × (wheel speed). The temperature it stands
for depends on rotor mass and cooling. For a different brake, scale k by (Nm/bar_new / Nm/bar_coded) ×
(r_tyre_coded / r_tyre_new) × (m_rotor_coded / m_rotor_new), and revisit the cooling (a, b) for the rotor's
mass and venting.

The ASR (engine) allows much less slip than brake TCS: DSC on ≈ 1.5 km/h, MDM 3–5 km/h.

### 5.2 Request bit [C]

`0xC96B8` sorts the rears:

- `0x402F83` b4 picks the leading wheel (more slip over its target, at ≥ 20 km/h and not split-µ);
- 0x402FAA / 0x402FAC = targets (lead, other), 0x402FAE / 0x402FB0 = filtered slips, 0x402FB2 / 0x402FB4 = PM.

`0xCA1E0` keeps **`0x402F6C` b6 (ASR request)** set while lead slip ≥ lead target + 0.10 km/h (−0.10 km/h once set).
Below 20 km/h or in split-µ it also accepts the other wheel, subject to further conditions with curve 0xF64F8 and
0x403068 / 0x4030A6 / 0x40309C [C structure].

### 5.3 Entry [C]

`tcs_b_entry` 0xCAD00, while ASR is inactive:

- **Condition:** 0x402F92 + 100 < 0x402F70 (engine torque, wheel-domain units) with the request bit b6, or
  `0x402F6C` b5 with 0x402F70 > 800. Otherwise 0x402F7A = 0x7FFF (no limit).
- **Start limit:** below 20 km/h with 0x402F7E b4 and a rear filtered slip < 5 km/h, `0xCA464` (if lower than the
  engine torque); at speed, 0x402F94 (or the engine torque when that is more than 130 above 0x402F94). Otherwise the
  current engine torque.
- **Activation** (`0xCACA4`): 0x402F7A = start; the cut 0x402FA4 = 0x402F70 − start is remembered for a later
  restore; `0x402F6C` b7 | b6 set.

### 5.4 Control [C structure; law open]

`0xCAF26` runs `0xCA1E0`, `0xC97AC` and, while active:

- `0xCAB4E`: floor 0x402F92; `0xCA94C` timed restore of 0x402FA4 into the limit (all, ½, or (t + 16)/34 of it at
  timer 0x402F9D events, while the lead slip is below target and 0x403068 < −200); then `0xCA860` (reduction while
  above target) or `0xCA006` (ramp 0x402F98 while the request bit is off);
- `0xCB81C` output stage, cals 0x40FDE–0x41010;
- `0xCA074` exit check (§5.5).

0x402F7C is a second torque value written only at activation, at exit and at init [C]. The closed form of the
reduction law (0xCA860 / 0xCA006 / 0xCB81C) is not derived (§12).

### 5.5 Exit [C]

`0xCA074`:

- **Exit request** (`0x402F83` b7):
  - when the limit 0x402F7A > 250 torque units (350 below 2300 rpm) and 0x402F7A − 0x402F7C − that margin > engine
    torque,
    and either driver demand 0x402F72 < limit or the gearbox flags 0x4010FA b7 / 0x4010FB b5 allow it;
  - or when the limit is still 0x7FFF, tcs_mode = 2 (DSC off), or pedal < 13.
- The request commits after counter 0x402F9E ≥ 19 frames, or at once below 18 frames into control when one rear is
  below the lower target and the other is negative.
- Exit: b7 clear, 0x402F7A = 0x7FFF, 0x402F7C = 0, 0x402F98 = 0, 0x402F88…90 = engine torque.

## 6. Channel C — MSR (engine drag torque control)

### 6.1 Slip [C]

`0xCCC8C` → `0xCCBE8`:

- d_L = front-left reference − RL raw, d_R = front-right reference − RR raw. The reference is rec+0x1C, set to ABS
  vref when the front axle is in ABS with both fronts flagged, decelerating, and AYC conditions hold (0x403046 b4),
  and adjusted around AYC front interventions.
- Filtered into `0x403042[L/R]` with N = 0x41066 = 90 (α ≈ 1/9). With rec+0x10 b4 and d < 10 km/h the input is
  2d − 10 km/h (≥ 0). Below N/10 = 0.09 km/h → 0.
- e = max(0x403042[L], [R]) (`0xCCDF6`); rate 0x403040 like §2.3 with N = 0x41064 = 90 (`0xCCE10`).

### 6.2 Target [R]

`msr_slip_target` 0xCCED4 (was `tcs_slip_target`):

```
T = curve(0x41046, vref_tcs)                  2.30 km/h to 50 km/h, 3.24 @ 80, 3.86 @ 100, 5.42 @ 150, 6.99 @ 200
if min raw slip < T: T ×2 (idle) or ×1.5 (MSR active)
if 0x400B09 b5: T ×1.5;      if AYC timer 0x40305B ≠ 0: T += 15 km/h
D = (FL + FR rec+0x22 accel)/2 + 0.05 g  (AYC-braked front excluded)
r8 = 0x4030A8 < 45 ? (D < 0 ? −8·D : 0) : 2·0x4030A8 − 90       (0 when the front axle is in ABS or 0x400B09 b5)
T = (front ABS ∧ 0x400B09 b5 ∧ a rear flag) ? r8 : T + r8
T += vM/20 (5 % of min(vref_tcs, ABS vref), unless 0x403046 b3) − curve(0x41030, 4·0x4030A8)
0x403054 = min(T, 300 km/h)
```

### 6.3 PID [C]

`msr_pid` 0xCD1E8 (was `tcs_torque_pi`), with gains from `msr_gains` 0xCD070:

- **Gear scaling:** pivot 0x41172 = 70. With i = 0x40306A (when 0x4030CD = 2 and 0x4030CC ≥ 1) or else S, the gains
  are multiplied by i/70 above the pivot and divided by trunc(70/i) (≥ 1) at or below it.
- **Gains:** Kp = 0x41076 = 60, Ki = 0x41074 = 100, Kd = 0x41072 = 180.
  - Ki is halved (≥ 10) while I > drag with positive error, and set to 0 when |rate| > 0.5 g with positive error.
  - Kd = 0 when the error is negative and the slip is rising again (rate ≥ 0).
  - Front axle in ABS with 0x400B09 b5: Kp = 0x41078 = 25 (½ below 5 km/h), Ki = Kd = 0 if a rear has rec+0 b5 or
    rec+0x10 b4; otherwise all gains are 0. In both cases I is reset.

```
err = e − T  (replaced by max_raw − T when that is ≤ 0 and lower)
D   = clamp(rate/10 · Kd / 100, 0x41068 = −2500, 0x4106A = 2500)                         → 0x403052
I  += Ki · clamp(err', 0x4106E = −200, 0x41070 = 200) · 10 / 100 / 1000;  0 ≤ I ≤ 2·drag → 0x40304A
      err' = err − T while I > drag, err − T < 1 and the slip is falling (faster unwind); else err
P   = err · Kp / 100                                                                       → 0x403050
u   = min(P + D + I, cap 0x40304E from 0xCD464)
u   = 0 if u < k·S/100,  k = 500 (decel ≤ −0.50 g) → 200 (≥ −0.25 g)   (decel = 0x408DAF)
active (0x40303C b7) if u ≥ 1:   0x40304C = u − drag
idle:                             0x40304C = −drag;  drag = (0x401148/10)·S/10   (engine drag torque, wheel domain)
```

FACTS cycle 4 called 0x41068 / 0x4106A the "P clamp" and 0x4106E / 0x41070 the "I clamp". They are the D-term
clamp and the integrator-input clamp. MSR only raises torque, and only while engine braking slows the rears.

### 6.4 DSC off [C]

There is no DSC-off inhibit. With `dme_0A8_flags` 0x40114F b4 and DME frames valid (0x401151 b2 clear), u is
capped at 6·S. In tcs_mode 2, u is then forced ≤ 0 (no request). Without that DME bit, **MSR stays active in DSC
off** (FACTS "DSC-off and the traction channels").

`dme_torque_request_compose` 0xCC2C2:

REDUCTION if ASR active (0x402F6C b7) or ABS 0x408D56 b7 or AYC 0x400B0A b6 or external (0x40460A b0 ∧ !0x40462E b7):

AYC's cap 0x400B30 and the ABS cap 0x408D58 only lower the limit. The external inputs come from the F-CAN aux

the stock image.

**CAN 0x0B6** (`can_dme_iface_update`, 0x7F530) [C]:

| Case | sig 20 (type) | sig 19 (0x4046E8) | sig 18 (0x4046E6) |
|---|---|---|---|
| reduction (b3) | **2** | 0x402F74·819/4096 | 0x402F76·819/4096 |

## 8. Coupling

### 8.1 Brake TCS ↔ engine ASR [C unless tagged]

The two channels run side by side: brake TCS works the brakes and ASR works the engine. The arbiter (§7) only merges
ASR with the AYC / ABS torque caps; nothing chooses between brake and engine. They interact as follows. The list
comes from a cross-reference of every channel A function against channel B RAM and the reverse.

1. **Ordering by threshold [I from C values].** Both read the same filtered rear slip `0x403086`.
   - ASR targets ≈ 1.5 km/h in m0 (3–5 km/h in MDM; §5.1).
   - Brake TCS enters at 8–10 km/h at 25–80 km/h and 16–20 km/h near standstill (§4.1).
   - So in a symmetric spin ASR cuts torque first. Brake TCS joins when one wheel keeps spinning well past the
     other despite the cut (one-wheel / split-µ spin).
   - No explicit priority rule was found; this follows from the numbers.
2. **Both rears spinning → brake TCS lets go.**
   - Below 30 km/h, `tcs_lowspeed_pair_exit` 0xC7D48 makes the rear with more pressure (or beyond 20 bar) exit when
     the other rear also spins (§4.2).
   - In MDM, the pair exit in 0xC7E40 does the same and sets `0x402FFF[w]` b1.
   - Braking cannot fix a symmetric spin, so this leaves it to the engine cut [I purpose]. The readers of
     0x402FFF b1 are not traced.
3. **ASR changes brake TCS's reference speed** (`tcs_front_tracker` 0xCD9D0, [R]).
   - With ASR active (`0x402F6C` b7) the front trackers hold 10 frames instead of 30 after a rise and fall
     0.05 km/h per frame instead of 0.11.
   - vref_tcs therefore stays higher, which lowers the slip that brake TCS sees.
   - In `tcs_vref_update` 0xCDBA0, with ASR active and the front axle in ABS (0x408DA2 b7) or 0x4030B5 > 90, the
     lower front tracker is pulled up to the higher one − 0.05 km/h (§2.1).
4. **Split-µ detection uses both** (`tcs_split_mu_detect` 0xC9A22).
   - It sets `0x402F7E` b7 from a sustained imbalance between the rear brake pressures (0x402FC4[2/3].+0, i.e. brake
     TCS at work) below 50 km/h, with ASR's limit 0x402F7A within 300 of its floor 0x402F92.
   - Effects on brake TCS: rate weight 2 % instead of 10 % (§4.1), no low-speed extra (E = 0), the split add-on
     0xC79E8 instead, release intervals ×5 (§4.4), and stricter exit (§4.2).
   - Effects on ASR: the request also accepts the second rear's slip (§5.2), the slip filter N = 110 (§2.3), and the
     target and sort logic change (0xC96B8, 0xCB38C).
5. **Brake TCS reads ASR: freeze override** (`tcs_a_phase_hint` 0xC846A → `0x402FFF[w]` b6, used in 0xC8576).
   - The freeze bit holds the brake demand at its old value (§4.4).
   - It is only evaluated when `rec+0x10` b4 is set (meaning open).
   - The freeze is cancelled when filtered slip > clamp(40 − vref, 0, 15) km/h, ASR is active and it is not split-µ.
     It is also cancelled in release when the engine torque 0x402F70 < 1500, under the same ASR condition.
   - So while the engine is already being cut and the wheel is still grossly over-spinning, the brakes keep
     adjusting instead of holding [I purpose].
6. **ASR reads brake TCS.**
   - `tcs_b_sort` 0xC96B8 copies the rear wheel pressures (0x402FC4[w].+0) into its sorted block 0x402FB2 / 0x402FB4.
   - In `tcs_b_request` 0xCA1E0, ASR's hold threshold r2 (compared with 0x40309C) is curve 0xF64F8(vref) normally.
     It becomes 15 km/h when 0x402F7F b1 is set, or when the side wheel's brake-TCS entry limit
     0x403018 / 0x40301A is 30000 (brake TCS off for it) **and** 0x402F7E b7 and b5 are both set (split-µ, low
     side). That is, ASR holds its request longer when it cannot rely on brake TCS for the low-µ wheel
     [C branch, I purpose; meaning of 0x40309C open].
7. **Inhibit link.** `0x402F6C` b5 (an ASR-side bit, writer open; also ASR's second entry path, §5.3) latches the
   brake-TCS inhibit through 0x403005 b4 in `tcs_a_inhibit_update` 0xCE3D0 (§3.2).
8. **Timing.** Brake TCS runs in slots 14 / 15 and ASR in slot 16 (§1.2). ASR therefore sees brake TCS's pressures,
   limits and active flag from the same 10 ms frame. Brake TCS sees ASR's flags (0x402F6C, 0x402F70) from the
   previous frame.
9. **Shared outputs and inhibits.**
   - The 0x19E TCS bit (bit 1) = brake TCS active (0x402FC0 b4) or (ASR active ∧ reduction request 0x402F6D b3) (§7).
   - The lamp's "TCS" state is ASR's state function 0xC7818.
   - MSR is inhibited while either channel (or AYC) is active (0x403048 b5).
   - DSC off and the fault-reaction bits (missing steering or DME) disable both (§3.2).
   - Only brake TCS has the 120 km/h entry cut-off, the disc-overheat cut-out and the engine-bog gate 0x403024.

### 8.2 Other systems [C]

- **ABS:**
  - the dispatcher skips `abs_pm_snapshot` while 0x402FC0 b0;

## 11. Corrections to earlier notes

- **Channel roles.** Channel C (`tcs_torque_pi` 0xCD1E8) is **MSR**, not the TCS torque-reduction PI (FACTS cycle 4).
  The ASR reduction is channel B (0xCAD00 / 0xCAB4E). Channel A is brake TCS. `msr_cycle_entry` 0xCBF58 (slot 16)
  is the **ASR** channel; slot 17 0xCC9A0 is MSR.
- **0x0B6 type.** 1 = increase (MSR), 2 = reduction pair; not "1 single = ASR".
- **0x19E bit 1.** It also covers active ASR with a reduction request, not only 0x402FC0 b4.
- **MSR clamps.** 0x41068 / 6A = D clamp, 0x4106E / 70 = integrator-input clamp.
- **"Entry gate" 0xC7D48** is the low-speed pair exit, not an entry gate.
- **Drive-slip "set A / set B".** The switch bit 0x402F6C b4 is gearbox type 1/3; 0xF625C is always used on the M3.
- **1M TCS block tail.** +0x8FE…+0x930 (37CE, 8B82, 0B3B, 9976, 6F9B) are the disc thermal-model constants, not
  integrity/id words (`agents/tcs/REPORT.md`).
- **Replayer bug.** `tools/mcore_replay.py` executed `clrt rx` / `clrf rx` as flag operations. They clear rx when
  C = 1 / C = 0 and leave C alone. Fixed in this pass. Replays of code containing them should be re-run; for example
  0x5E936–0x5FA2A has three.
